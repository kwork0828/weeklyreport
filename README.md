# 주간업무보고 자동화 검토 결과

업로드해주신 자료(취업설문 응답, 개인_상담일지, 실제 다운로드해서 만드신 피벗 파일, 23/30주차 보고 메일 2건)를 바탕으로 현재 프로세스를 정리하고, 자동화 가능한 범위를 나눠 Google Apps Script 초안(`apps-script/`)을 만들었습니다.

## 1. 현재 프로세스 요약

매주 화요일 낮 12시(응답 마감 화요일 오후 1시)를 기준으로, 지난주 화요일 ~ 이번주 월요일 사이 상담 내역을 정리해서 3개 섹션(① 상담 현황 표, ② 프로그램 현황, ③ 특이사항)으로 보고합니다.

| 섹션 | 지금 하시는 방식 | 데이터 출처 |
|---|---|---|
| ① 상담 현황 (기수 x 상담방법 건수표) | 상담일지 다운로드 → 새 엑셀에 붙여넣기 → 피벗테이블 생성 | 개인_상담일지 `★일일상담현황★` 탭 |
| ② 프로그램 현황 (소그룹컨설팅/취업스터디자문/미니상담부스/모의면접 등) | 기억/메모 기반 수기 작성 | 일부는 상담일지에 `상담구분`으로 남지만, 주간채용알림·취업세미나는 아예 기록되지 않음(규정상 상담일지 미작성 대상) |
| ③ 특이사항 – 컨설팅 | 기수별로 자소서/면접 컨설팅한 기업명 수기 작성 | 상담일지 `잡매칭1~5` 컬럼에 기업명이 남아있음 |
| ③ 특이사항 – 취업자 | 담당 반 학생이 취업설문에 응답하면 확인 후 수기 작성, 확정되면 `구미캠퍼스 교육생` 탭에 별도 업데이트 | 취업 및 취업준비현황 파악(응답) 스프레드시트 vs `구미캠퍼스 교육생` 탭 대조 |

## 2. 자동화 가능 범위

- **완전 자동화 가능**: ① 상담 현황 집계표. 지금 하시는 "다운로드 → 새 엑셀 → 붙여넣기 → 피벗" 과정 전체가 그대로 대체됩니다. 이 과정이 필요했던 이유(구글시트에서 직접 피벗 만들면 엉킴)는 Apps Script가 원본 시트를 직접 읽기만 하고 쓰지 않기 때문에 애초에 발생하지 않습니다.
- **부분 자동화**: ③ 취업자 파악. 취업설문 응답과 `구미캠퍼스 교육생` 탭을 자동 대조해서 "이번 주 새로 확인된 취업자"만 뽑아내고, 보고서 문구 형식(`기업명(직무)_이름(기수N반)_취업일 (컨설턴트명) 취업설문(완료/예정)`)까지 자동 생성합니다. 다만 동명이인·명단에 없는 이름은 사람이 확인해야 합니다. `구미캠퍼스 교육생` 탭 반영도 자동화했지만, 오반영 위험 때문에 **명단에서 1명만 정확히 매칭된 경우에만, 메뉴를 눌러야** 반영되게 만들었습니다(자동 트리거로 조용히 쓰지 않음).
- **부분 자동화**: ③ 컨설팅 내역. `잡매칭` 컬럼에 기업명이 남아있는 상담 건만 기수별로 모아 초안 문구를 만들어줍니다. 다만 "권역" 표기, 자연스러운 문장 다듬기는 사람이 마무리해야 합니다.
- **자동화 불가(수기 유지 필요)**: 주간채용알림, 취업세미나 — 규정상 상담일지에 남기지 않는 항목이라 원본 데이터 자체가 없습니다. 별도로 참여 인원/일자를 기록하는 곳이 생기지 않는 한 자동화할 수 없습니다.

## 3. 추천 아키텍처 — Google Apps Script

세 가지 방식을 검토했습니다.

| 방식 | 장점 | 단점 |
|---|---|---|
| **Google Apps Script (채택)** | 데이터가 이미 Google Sheets에 있어 별도 인증/서버 불필요, 무료, 스프레드시트에 메뉴로 바로 붙일 수 있음, 매주 화요일 자동 트리거 가능 | 자연어 요약(문장 다듬기)은 못 함 |
| 외부 스크립트 + Google Sheets API | 더 강력한 로직 가능 | 서비스 계정/OAuth 관리, 실행 서버(또는 스케줄러) 필요 — 개인 업무 자동화치고 과함 |
| Claude(LLM) 기반 주간 실행 | 상담내용 원문을 읽고 자연어로 요약 가능 | 매주 정확히 같은 계정/세션에서 실행되도록 유지보수해야 하고, 시트 특정 셀 쓰기 등 정밀 제어가 Apps Script만큼 안정적이지 않음 |

**결론**: 핵심 엔진은 Apps Script로 구현하고, 사람이 매주 5분 정도 검토/다듬기만 하는 구조를 추천합니다. 나중에 여유가 되면 "① 자동집계 + ③ 취업자 자동대조" 결과를 Claude에게 붙여넣어 문장만 다듬어달라고 하는 정도로 보완하면 충분합니다.

## 4. `apps-script/` 폴더 구성

- `Config.gs` — 스프레드시트 ID, 본인 이름, 담당 기수/캠퍼스 등 환경설정 (가장 먼저 확인/수정할 파일)
- `Utils.gs` — 날짜 범위 계산, 시트 읽기 공통 함수
- `ConsultationSummary.gs` — ① 상담 현황 표, ② 프로그램 현황 초안, ③ 컨설팅 초안
- `NewHires.gs` — 취업설문 vs 교육생 명단 대조, 신규 취업자 판별, 명단 반영
- `ReportBuilder.gs` — 전체 보고서 텍스트 조립 + Google Doc 생성
- `Menu.gs` — 스프레드시트 커스텀 메뉴 + 화요일 자동 트리거 등록

## 5. 적용 방법 (가장 빠른 방법 — 파일 1개만 붙여넣기)

`apps-script/AllInOne.gs`는 아래 6개 파일을 하나로 합친 버전입니다. 이것만 써도 동일하게 동작합니다.

1. `개인_상담일지` 구글시트를 엽니다. → 확장 프로그램 → Apps Script.
2. 기본으로 열려있는 `Code.gs` 안의 내용을 전부 지우고, `AllInOne.gs` 내용을 통째로 붙여넣습니다.
3. 상단 저장(💾) 클릭.
4. `CONFIG` 상수 안의 `CONSULTANT_NAME`, `MY_COHORTS`, `MY_CAMPUSES`, `CURRENT_STUDENT_COHORTS` 값을 본인 상황에 맞게 확인·수정합니다(스프레드시트 ID는 이미 채워뒀습니다).
5. 나머지 실행/권한승인/메뉴 확인 절차는 아래 6번부터 동일합니다.

### 파일을 나눠서 관리하고 싶다면 (선택)

1. 위 1번까지는 동일.
2. 아래 6개 파일 내용을 그대로 각각 새 스크립트 파일로 만들어 붙여넣습니다(파일명은 `.gs` 확장자로, `Code.gs` 기본 파일은 지워도 됩니다).
3. `Config.gs`에서 `CONSULTANT_NAME`, `MY_COHORTS`, `MY_CAMPUSES`, `CURRENT_STUDENT_COHORTS`, 각 시트 ID를 본인 상황에 맞게 확인합니다(스프레드시트 ID는 이미 채워뒀습니다).
4. 스프레드시트를 새로고침하면 상단에 **"주간보고 자동화"** 메뉴가 생깁니다.
5. 처음에는 "이번 주 초안 미리보기"로 결과를 확인해보고, 컬럼 위치나 상담방법 명칭이 실제 시트와 다르면 `Config.gs`의 `LOG_COL` / `METHOD_MAP` 등을 조정하세요.
6. 문제 없으면 "매주 화요일 09:00 자동 실행 등록"을 눌러 매주 아침 초안 Google Doc이 자동 생성되도록 설정합니다.

## 6. 남은 한계 및 다음 단계 제안

- 취업설문 "입사일" 컬럼이 자유 텍스트(`2026년8월10일`)라서 형식이 어긋나면 파싱이 실패할 수 있습니다 — 초안에 "(입사일 확인 필요)"로 표시되니 그 부분만 확인하면 됩니다.
- 동명이인(`김건우A`처럼 표기)은 자동 매칭이 안 되니 항상 사람이 봐야 합니다.
- 주간채용알림/취업세미나는 원본 데이터가 없어 자동화 대상에서 제외했습니다. 이 두 항목도 자동화하고 싶으시면, 참여 인원을 기록하는 별도 시트(간단한 구글폼 등)를 하나 만드시는 걸 권장드립니다 — 그러면 이 스크립트에 집계 함수 하나만 추가하면 됩니다.
- 이메일 발송까지는 자동화하지 않았습니다(초안 Doc만 생성). 매주 문구를 다듬어야 하는 서술형 항목이 있는 한, 사람이 최종 확인 후 보내는 게 안전합니다.
